## What the suites cover

- `backend/tests/integration/test_role_matrix.py`: every one of the 9 roles against 24 guarded endpoints
  (allowed vs. 403), unauthenticated 401s, read-only roles, business-unit scoping across findings,
  exceptions, CSV export and dashboards, AI scope, CSV formula-injection, config auditing, lockout, user-role validation.
- `backend/tests/integration/test_spec_features.py`: survivorship, failed-row retry, reopen-on-redetection, threat-feed
  rescoring, attack-path influence preserved on rescore, asset registration/criticality rescoring, ownership routing,
  reassignment, task→finding closure, policy-driven escalation, acknowledgement and inbox, SLA report and breach
  forecast, ticket lifecycle and signed webhook, exception review pack, MFA enrollment/login/rotation, password policy,
  audit hash-chain tampering detection and append-only triggers, secret-key validation, reports, AI entities/follow-ups,
  graph export.
- `backend/tests/integration/test_seeded_smoke.py`: every read endpoint on the full synthetic seed.
- `backend/tests/unit/*`: risk engine, upload parser, AI assistant, forecasting model.
- `frontend/src/**/*.test.ts(x)`: permission-driven navigation and guards, token refresh (single-flight), paging.
- `e2e/workflows.spec.ts`: 13 role-based workflows (see `11_Test_Cases.md`).

## Not verified in this environment

Docker/PostgreSQL runtime and gitleaks (tools not installed locally; both run in `.github/workflows/ci.yml`),
the optional Claude path (no API key) and the Kubernetes manifests (YAML-validated only).
